Python · Screen before signing
from sekisho import SekishoClient, SekishoError

USDC = "0x036CbD53842c5426634e7929541eC2318f3dCF7e"


async def screen_payment(counterparty, gate_url="http://localhost:8000"):
    async with SekishoClient(gate_url) as gate:
        try:
            decision = await gate.screen(
                counterparty=counterparty,
                direction="outbound",
                amount="50000",  # 0.05 USDC, in atomic units
                asset=USDC,
                payment_chain_id=84532,  # Base Sepolia
                source="direct",
                agent_id="my-agent",
            )
        except SekishoError:
            return "HOLD"  # No usable decision: do not sign.
        return decision.verdict

Install the SDK, start your gate, then call await screen_payment(counterparty). This screens only; signing requires ALLOW. Use the x402 hooks to enforce it in the payment flow.

Before you
try it.

Can I explore without API keys?

Yes. Try the guided simulation above, or clone the repository and run the console's fixture preview. It uses synthetic cases and browser-only simulations, with a visible fixture banner. Follow the quick start.

Is the live payment stack deployed?

Not yet. The components are implemented and locally tested. Live service configuration, testnet contract deployment, and the complete payment rehearsal remain pending. See the readiness checklist.

Does an ALLOW mean a wallet is safe?

No. It is a point-in-time decision under the configured demo policy, based on available evidence. Sekisho is not a certified AML programme or legal advice.

Where do payments happen?

The project's value-transfer and contract chain is Base Sepolia. Ethereum and Base mainnet are used read-only for screening. The public website makes no payments and does not connect to a wallet.
